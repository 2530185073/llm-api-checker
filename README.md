# LLM API 鉴真（模型指纹 + 渠道成分 + 降智检测）

一个可自托管的 Web 工具：填入中转站 / 第三方 LLM 接口的 **Base URL** 与 **API Key**，选择一个或多个模型（可从 `/v1/models` 拉取后点选，也可手动输入），一次检测输出三份报告，多个模型时再给出并排对比矩阵：

1. **模型指纹报告**：声称的模型 vs. 最可能的实际模型，附置信度与逐条证据（数字指纹、分词器探测、响应元数据、自报身份）。
2. **渠道成分报告**：按厂商（Claude / OpenAI / Gemini / GLM / Kimi / DeepSeek）运行协议保真、流式语法、usage 计费算术、参数校验、思考与工具、上下文阶梯、分词器指纹、身份与注入检测等用例，给出加权「成分得分」、关键问题标记与结论。
3. **降智报告**：8 道带标准答案的问答题 + 22 道 HTML/SVG 动画题（结果在页面上直接渲染预览），可每题重复 N 次，给出通过率、平均 / P95 耗时与标准差，以及加权“智力得分”。

支持 OpenAI **Chat Completions**（`/v1/chat/completions`）、OpenAI **Responses**（`/v1/responses`）、Anthropic **Messages**（`/v1/messages`）三种协议，可自动识别也可显式锁定（见下文「接口协议」）。界面为简体中文，适配手机。

> 没有 Key 也能体验：页面上点击「使用演示端点」，会使用内置的模拟上游 `/api/mock/v1`。它包含 6 家厂商的正常渠道（`claude-sonnet-4.6`、`gpt-5.4`、`gemini-3.6-flash`、`glm-5.3`、`kimi-k3`、`deepseek-flash`）与两个掺假渠道：`claude-opus-4.8`（OpenAI 格式转换 + Claude Code 逆向 + 降智，实际是另一家模型）和 `deepseek-v4-pro`（低精度量化的自部署后端，实际是另一个模型、窗口只有 128K、usage 不完整）。

## 快速开始

需要 Node.js ≥ 22。

```bash
npm install
npm run dev          # 开发模式，http://localhost:43117
```

生产运行（单条命令）：

```bash
npm install && npm run serve     # 构建 + 预下载参考数据 + 启动，默认端口 43117（可用 PORT 覆盖）
```

### Docker

```bash
docker build -t llm-api-checker .
docker run -d -p 43117:3000 --name llm-api-checker llm-api-checker
# 或
docker compose up -d
```

打开 <http://localhost:43117>。镜像构建时会预先下载指纹参考数据（约 3.6 MB）；若构建环境无法联网，会在第一次检测时再下载。

### 环境变量

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `43117`（Docker 内为 `3000`） | 监听端口 |
| `ALLOW_PRIVATE_TARGETS` | 开发模式允许，生产模式禁止 | 设为 `1` 允许检测 localhost / 内网地址（例如本机的 one-api、new-api）。公网部署建议保持禁止，避免被当作 SSRF 跳板 |
| `MAX_CONCURRENT_CHECKS` | `4` | 单实例同时进行的检测任务上限（一次多模型检测算一个任务） |
| `LMFPD_CACHE` | `/tmp/lmfpd/data.bin` | 参考数据缓存文件 |
| `LMFPD_DATA_SOURCE` | 空 | 参考数据来源；可填镜像 URL（以 `/` 结尾）或本地数据目录（完全离线） |

## 隐私与安全

- API Key（含可选的对照官方 Key）只放在发往本服务后端的请求体里，由后端在本次检测期间转发给对应接口（`Authorization: Bearer`，Messages 协议同时带 `x-api-key`，Gemini 带 `x-goog-api-key`），**不写日志、不落盘、不回传**；进度流和报告中出现的 Key 会被替换为 `[REDACTED]`。
- 后端代理可以避开浏览器的跨域限制，但也意味着服务端会访问任意 URL：生产模式默认拒绝内网 / 回环地址，且不跟随重定向。
- 指纹 + 降智默认约 27 次请求；渠道成分检测按清单不同约 150–400 次请求，其中上下文阶梯会发送数十万 token 的长请求（可用「上下文阶梯档位上限」控制），重复次数与模型数会成倍放大请求量。这些都会产生真实费用，可在清单里按需取消。

## 接口协议

表单顶部的「接口协议」有四个选项：

- **自动识别**（默认）：按 Chat → Responses → Messages 的顺序各发一条最短请求探测（模型名像 Claude 时 Messages 优先），用第一个可用的协议跑指纹与降智检测。GPT 渠道通常落在 Chat。成分检测按厂商原生协议进行；若探测时前面的协议不可用（例如渠道只开放 `/v1/responses`），成分检测也会锁定到探测出的协议。
- **Chat Completions / Responses / Anthropic Messages**（显式选择）：全程锁定所选端点。指纹、分词器探测、问答题、动画题和成分检测都只发这一种生成请求，失败时直接报错，**不会回退或改用其他协议**。成分检测中只适用于其他协议的用例（如 OpenAI 的 `n`、`stop`、`json_schema` 属于 Chat；`previous_response_id`、内置 `web_search` 属于 Responses；Claude / Gemini 原生用例、DeepSeek 的 Anthropic 格式与 FIM）会标注「仅适用于 …；协议已锁定为 …，按设置跳过」。两种协议都有的 OpenAI 用例（基础对话、developer 角色、多轮、TTFT / 吞吐、ID 格式、usage 明细、图片、推理强度、身份与一致性等）会按所选协议发送。跳过项过多导致证据不足时，结论为「无法判定」而不是「官方」。
- 需要在固定协议的同时跑厂商原生用例，可在成分检测设置里打开「允许厂商原生协议（跨协议）」。它只影响成分检测，指纹与降智检测仍只用所选协议。

**Base URL 规范化**：只写到域名（`https://api.example.com`）时补 `/v1`；写到 `/v1` 原样使用；粘贴完整端点（`…/v1/chat/completions`、`…/v1/responses`、`…/v1/messages`）时去掉端点后缀，并且：自动识别模式下直接使用该端点对应的协议并锁定（报告显示「按 URL 推断」）；显式选择了不同协议时拒绝开始并提示冲突。

演示端点支持用 Key 模拟单协议渠道：Key 中包含 `only-chat` 时除 `/v1/chat/completions` 外的生成端点都返回 404，包含 `only-responses` 时只开放 `/v1/responses`。`GET /api/mock/_log`（带同一个 Key）返回该 Key 按路径统计的请求次数（Key 只以哈希形式驻留内存），可用来确认检测没有发出其他协议的请求。

## 多模型、重复与并发

- **多模型**：一次最多选 12 个模型，所有模型共享一个「全局并发」上限（1–16）同时检测。结果页先给出对比矩阵（综合评分、指纹判定与最可能的模型、成分得分与关键问题、智力得分、首字 / 平均耗时、请求数、逐题通过率与 P95），点击模型名下钻到该模型的完整报告。
- **重复 N 次**：降智检测的每道问答题与动画题并发执行 N 次（1–10），逐题给出每次结果、通过率、平均 / P95 耗时与标准差；智力得分按通过率加权。动画题会把 N 份预览并排展示。

## 渠道成分检测

每个模型按厂商使用对应的用例清单（默认按模型名判断，也可手动指定渠道类型）。清单在「用例清单」对话框中按分组列出，每条用例显示权重与标签（前置 / 不计分 / 关键 / 收尾 / 默认不勾选 / 官方链路特征 / 需对照端点），可按厂商一键「默认 / 全选 / 全不选」或按分组勾选。

| 厂商 | 用例数 | 主要分组 |
| --- | --- | --- |
| Claude（Messages） | 61 | 连通性、协议保真、流式、高级特性、身份 / 成分、压力 |
| OpenAI（Chat / Responses） | 30 | 连通性、协议保真、流式、高级特性、身份 / 成分 |
| Gemini（generateContent） | 30 | 连通性、协议保真、流式、高级特性、身份 / 成分 |
| GLM | 64 | 端点画像、usage 计费完整性、与官方对照（精度 / 性能）、上下文窗口、参数校验、思考、工具、流式、身份 / 成分、压力 |
| Kimi | 59 | 同上，另有请求签名、缓存选项、动态加载工具、Partial 续写 |
| DeepSeek | 57 | 同上，另有硬盘缓存、logprobs、Beta 前缀续写 / FIM、Anthropic 格式端点、Responses API |

**用例结果**：通过 / 警告 / 失败 / 跳过 / 只记录。**成分得分** = Σ(权重 × 结果分) ÷ Σ 权重（通过 1、警告 0.5、失败 0，跳过与只记录不计入）。出现关键问题标记（模型被替换、usage 造假、上下文被截断、疑似低精度、Claude Code 逆向；要求官方链路模式下还有非官方后端、协议转换层、注入系统提示）或关键用例失败时，结论封顶为「检出关键问题」。

**评分模式**（GLM / Kimi / DeepSeek）：

- **官方等价（允许自部署）**：只看模型、上下文、思考、计费、精度、性能是否与官方一致；官方链路特征（id 形态、错误码、参数校验、/models、响应头等）只记录、不计分、不封顶。
- **要求官方链路**：在等价基础上，官方链路特征按各自权重计分，非官方后端 / 协议转换层 / 注入系统提示也会封顶结论。

**精度综合判定**：精度题组（随机串复制、排序、字段召回、逐项变换、算术链）、长上下文多针召回、KV 缓存差分复制、贪心分歧、思考画像、分词计数等用例各自给出「强 / 弱 / 无」精度证据，强证据 2 分、弱证据 1 分，合计 ≥ 4 才判疑似低精度。

**usage 审计**：本次运行中的每个 200 响应都会被记录，收尾用例统一检查 `total = prompt + completion`、`cached ≤ prompt`、`hit + miss = prompt`、`reasoning ≤ completion`、有输出则 `completion ≥ 1` 等不变量，算术不成立判 usage 造假。

**分词器指纹**：用差分计数探针测出上游分词器，并与 62 类开源分词器的真实计数比对，对照各厂商官方分词器（OpenAI o200k、Gemini Gemma 3、GLM-5 / GLM-4、Kimi、DeepSeek-V3 词表）。

**可选输入**：填写「对照官方端点」后启用对照类用例（分词计数比对、贪心分歧、吞吐 / 首字延迟对比、工具定义计数、精度题组 ΔS 等）；填写「第二模型」后启用两个模型名是否同一后端的判断。「上下文阶梯档位上限」控制长上下文用例的最大长度（默认 256K，设为 1M 才会验证 1M 窗口顶部）。

## 检测原理

### 模型指纹

- **数字指纹**（依赖 npm 包 `lmfpd-sdk` 及其运行时下载的参考数据）：随机生成 3 道挑战，要求模型凭第一反应写出约 300 个 1–355 的整数（中 / 英 / 日 / 韩 / 法随机措辞，禁止工具和规则化序列）。语言模型的“随机数”并不均匀，每个模型偏好的数值、区间、末位数字相对稳定；检测器把数值分布（Hellinger 嵌入）、位置分段与末位分布、位置核、序列特征与参考库中 69 个模型对比，用 LDA / 近邻 / 去干扰中心的组合排名，并用温度 softmax 给出**参考库内**置信度。先做“序列形态检查”（lag-1 自相关、小步长占比），排除程序生成的数字。
- **分词器探测**：差分计数 + 贝叶斯开集判定。每个探针只发 `前缀 + 测试文本 + 后缀`，用 `usage` 中输入 token 数减去只含前后缀的对照请求，抵消聊天模板与隐藏系统提示；按成对 Bhattacharyya 上界自适应挑选探针（最多 12 条），在 62 类开源分词器与“未收录”之间判定，再与所填模型的官方分词器（如 OpenAI 新模型为 o200k_base）核对。
- **响应元数据**：响应中的 `model` 字段、响应 ID 格式（`chatcmpl-` / `resp_` / `msg_` / `gen-`）、`system_fingerprint`、部分响应头。
- **自报身份**：询问“你是哪个模型”，只作弱证据。

声称模型与指纹结果的关系分为：一致、同家族不同型号、不一致、参考库未收录、无法判断。

### 降智检测

包含三部分：

| 检测 | 内容 |
| --- | --- |
| **问答题**（自动判分） | 8 道有标准答案的题目，比较最终可见答案与耗时 |
| **HTML/SVG 动画题** | 12 道内置题：鹈鹕骑自行车（默认）、北极熊骑自行车、奥特曼骑摩托车、章鱼打架子鼓、长颈鹿踩滑板、宇航猫月球钓鱼、模拟时钟、太阳系轨道、弹跳小球物理、齿轮传动、城市夜景视差、汉字笔顺；报告中沙箱预览 + 自动检查 + 人工目测要点 |
| **Grok 思考证据** | 所填模型含 grok 时生效：有可见输出但全程没有思考内容即视为降智；不信任 usage 中虚报的 reasoning_tokens |

**问答题**：答案先做 Unicode NFKC 标准化、去首尾空白和包裹整个答案的单层代码围栏，再按 `exact` / `contains` / `regex` 判定；判定方式可选 `answer`（只看答案，默认）、`latency`（耗时严格小于题目阈值）、`both`；状态分为正常 / 未通过 / 请求失败，**请求失败不计为答错**。

| 题目 | 考察 | 权重 |
| --- | --- | --- |
| 糖果配对 | 复杂推理 | 3 |
| 容斥计数（1–1000 中不被 2、3、5 整除的个数） | 数学推理 | 2 |
| 7^2026 的末两位 | 数学推理 | 2 |
| 同余方程（中国剩余定理） | 数学推理 | 1 |
| Python 代码推演 | 代码理解 | 2 |
| 字符计数 | 细节注意力 | 1 |
| 严格 JSON 输出 | 指令遵循 | 1 |
| 长文本口令检索（约 2–3k tokens，口令每次随机） | 上下文完整性 | 2 |

数字题使用 `number` 匹配：取回答中的最后一个数字与标准答案比较，最多允许出现 2 个数字，防止“列举多个候选”蒙混过关。

**HTML/SVG 动画题**：请求附带系统指令（要求返回内联全部 SVG/CSS/JS 的完整 HTML），从回答中提取 HTML，在报告里用 `sandbox="allow-scripts"`（不含 same-origin）+ 严格 CSP 的 iframe 渲染，可重新播放、查看源码、下载 HTML，并列出 4 项人工目测要点（形态是否可辨、机构是否合理、动作是否连贯、场景与代码是否完整）。自动检查加权得分 ≥ 75 记为通过：

| 检查 | 权重 |
| --- | --- |
| 提取到可渲染的 HTML / SVG | 2 |
| SVG 结构有效（标签嵌套与闭合） | 2 |
| 输出完整未截断（正常闭合、非长度截断） | 2 |
| 包含动画（SMIL / CSS / JS） | 2 |
| 画面元素符合题意（如鹈鹕：喙 / 喉囊 / 翅膀；自行车：车轮 / 踏板 / 辐条） | 2 |
| 图形足够丰富（≥ 15 个基本图形元素） | 1 |
| 体积合理（2 KB – 512 KB） | 1 |
| 不引用外部资源 | 1 |

除上表 12 道题外，另有 10 道动画题：灯塔夜巡、牛顿摆、蜂鸟采蜜、风车农场日落、火箭发射、海底水族箱、心电监护仪、十字路口红绿灯、折纸鹤、DNA 双螺旋，同样带主题关键词检查。

动画题的耗时阈值为 180 秒（仅在 `latency` / `both` 判定方式下计入），超时上限可选 10 / 20 / 30 分钟；Messages 协议下 `max_tokens` 为 32768（被拒时自动降到 8192）。鹈鹕题权重 2，其余动画题权重 1。

**智力得分** = 通过题目权重之和 ÷ 有效题目权重之和 × 100；≥ 85 为正常，60–85 为疑似降智，< 60 为明显降智；有效题目权重不足一半时为“无法判断”。额外信号：响应模型名与请求不一致、多次请求返回不同模型、请求了推理强度却没有推理 token、推理 token 只出现在用量里、输出被截断、长文本题输入 token 异常偏少。

**综合评分** = 智力得分 × 指纹系数（一致 1.0、参考库未收录 0.9、同家族 0.75、不一致 0.4）；启用成分检测时再按 6 : 4 与成分得分加权（成分检出关键问题时成分得分按不超过 40 计）。只完成一部分时取已完成部分的结果。
